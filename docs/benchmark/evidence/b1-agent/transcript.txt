  **Files to change in src/:**
  - `TodoItem.cs`: new `UserId` property. `Clone()` must copy it too.
  - `ITodoRepository.cs`: `GetAllAsync` gets an optional `userId` parameter
  before the cancellation token. The same filter goes into both
  `InMemoryTodoRepository` and `JsonFileTodoRepository`.
  - `TodoItemDto.cs`, `CreateTodoItemRequest.cs`, `UpdateTodoItemRequest.cs`:
  new `UserId` property.
  - `TodoMapper.cs`: new helper `NormalizeUserId`, used in `ToDto`, `ToEntity`
  and `ApplyTo`.
  - `TodosController.GetAll`: new `[FromQuery]` `userId` parameter with the
  length check, plus a documented 400 response.

  **Design decisions:**
  - **Validation:** `userId` is optional, at most 100 characters. The same limit
  applies to the create body, the update body and the query parameter.
  - **Trimming:** the value is trimmed in the mapper. Empty or whitespace-only
  becomes null, and an empty `?userId=` means no filter.
  - **Matching:** exact and case-sensitive (`alice` and `Alice` are different
  users). It combines with `isCompleted` as AND. Todos without a `userId` never
  match a `userId` filter but still appear when no filter is given.
  - **PUT without `userId`:** PUT is a full update, so leaving `userId` out
  clears it, the same as `description` today.
  - **Existing JSON files:** they load with `UserId = null` and need no
  migration. `UserId` must not be marked `required`, or old files would be
  treated as corrupt.
  - **`POST /api/todos/repeat`:** I left it out of scope. Its items get `UserId
  = null`.

  **Required changes outside the new feature:**
  - `PerformanceProfilingTests.cs` calls `GetAll(null, ct)` by position. It must
  become `GetAll(null, null, ct)` or the build fails. Nothing else in that test
  changes.
  - The rules make README.md and README.cs.md part of the doc update, not just
  `docs/OpenAPI.md`. Their API endpoints table needs the new `?userId=` filter,
  in English and in Czech.

  **Tests (29 new):**
  - 5 mapping tests and 4 DTO validation tests (new file
  `DTO/TodoUserIdValidationTests.cs`).
  - 3 controller tests.
  - 5 tests for the in-memory repository and 3 for the JSON repository,
  including one that loads an old JSON file without a `userId` field.
  - 9 integration tests in the new file `Integration/UserTodoFilterApiTests.cs`.
  They swap in an empty in-memory repository the same way
  `RecurringTodoApiTests` does, so no developer data is touched.
